StarFlow Components tokens · v0.1

Design Tokens

三层变量：原始值只给语义层取值，组件只消费语义层，单个组件的默认值和覆盖钩子留在第三层。换主题只覆盖语义层，所以加一个主题不用碰任何组件。

L1 Primitive原始值，只给 L2 引用
→
L2 Semantic组件只消费这一层
→
L3 Component单个组件的钩子
全局变量 — 组件 token — 生效主题 — 依赖 0
01 / PRIMITIVE

原始色阶

只作为 semantic 的取值来源，组件直接引用就等于把皮肤写死在组件里。状态色亮色取 600、暗色取 400，是为了两边都过对比度。

02 / SEMANTIC

语义色

组件里只该出现这些名字。*-subtle 是用 color-mix 从主色现算的浅底，省掉一整套浅色 primitive，也保证换主题时浅底自动跟着走。

03 / COMPONENT

组件 token

第三层只服务一个组件，默认值声明在组件自己的 :host 上，不进全局样式表 —— 组件删了，它的 token 跟着走。它只在两种情况下成立：语义层没有能直接表达的值（高度、密度这类组合值），或者要给外部留一个按实例覆盖的稳定钩子。单纯把语义变量改个名不算理由，那只是多一层查表。

默认 次要 小号 禁用
试一下 只改这一个实例

写 sf-button { --sf-button-bg: … } 能整批换色，不用 !important；但写在祖先容器上的变量进不来 —— 继承输给 :host 里的声明，要命中按钮本身。

04 / SPACE

间距

4px 网格，数字即倍数。space-4 就是 16px，不用回表查。

05 / TYPE

字号

正文 14px 起步，UI 密度偏紧。行高单独成 token，组件里不写魔法数。

06 / SHAPE

圆角与阴影

阴影是语义层的一部分 —— 暗色下它得换一套更黑更重的值，否则卡片在深底上等于没有层次。

07 / MOTION & Z

动效与层级

系统开了「减少动态效果」时，三个时长会被归零，组件写 transition 不必各自判断。

08 / COMPOSE

组合预览

按钮已经是真的 <sf-button>，输入框和徽章还是临时手写的 —— 它们只用变量、没有一个硬编码色值，换主题时整块跟着变。等它们也变成组件，第三层就各自跟着组件走。
